# Semantic Engine — AI tool reference

_Generated by `node scripts/gen-ai-tools-doc.js` from the tool registry; do not edit by hand._

27 tools. They are served over MCP (`tools/list`, `tools/call`). Through the gateway each tool also takes a `project` parameter.

Every result is `{ success, items[], metadata, context? }` with `projectId` and `indexGeneration` added by the server; see the skill (`skills/semantic-engine/SKILL.md`) for how to read `truncated`, empty results and `warnings`.

## Orientation

### `project_info`

Call this first in a session. It tells you which languages are indexed, how deep the analysis goes for each (symbols only, or call graph too) and how old the index is, so you know how far to trust the other tools.

_No parameters._

**Returns.** Project root, index time, languages and per-language support (symbols / callGraph / status).

### `list_files`

List indexed files to learn the layout or to get exact paths for the other tools. Generated, vendored and ignored files are already left out.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | optional | Only files whose path contains this text (a folder prefix such as "src/gateway/"). |
| `language` | string | optional | Only files of this language id. |
| `limit` | integer | optional | Maximum files returned (default 100). _(min 1, max 1000, default 100)_ |

**Returns.** Files in path order with language, size and line count. `matchCount` holds the real total when the list was cut.

### `diagnostics_get`

Read compiler/language-server diagnostics stored in the index.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | optional | Project-relative file path using forward slashes, exactly as printed by list_files. Omit for project-wide diagnostics. |
| `severity` | string | optional | Only this severity, e.g. "error" or "warning". |
| `limit` | integer | optional | Maximum diagnostics returned (default 1000). _(min 1, max 10000)_ |

**Returns.** items[]: diagnostics (message, severity, code, line, column). metadata.warning is present when no diagnostics pass was recorded — then an empty list does NOT mean the code is clean.

## Finding things

### `find_context`

Start here for a task in code you do not know: describe the task in plain words and get the files and symbols that matter, each with the reason it was chosen. One call replaces a round of Grep/Glob guesses, because it follows imports and call edges from the first hits. Set includeSource (or pass files/symbols you already know) to get the relevant source assembled within a token budget.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `task` | string | required | One or two sentences describing what you want to do or understand. |
| `includeSource` | boolean | optional | When true, return assembled source text instead of a list of candidates (default false). _(default false)_ |
| `files` | string[] | optional | Project-relative paths you already know are involved; always included, and implies includeSource. |
| `symbols` | string[] | optional | Symbol names, ids or "path::name" you already know are involved; implies includeSource. |
| `maxTokens` | integer | optional | Token budget of the assembled source (default 4000); only used with includeSource. _(min 500, max 32000, default 4000)_ |
| `includeTests` | boolean | optional | Include test files linked to the candidates. |
| `limit` | integer | optional | Maximum candidates returned when listing (default 20). _(min 1, max 100, default 20)_ |

**Returns.** Candidates with a relevance score and why each was selected (search hit, architecture module, graph neighbour). With includeSource: the assembled source text of the targets, related files and tests.

### `search`

Find code when you do not have an exact name. mode "meaning" (default) ranks symbols and files by a plain-language description, which Grep cannot do. mode "text" is a case-insensitive substring search that also reports the enclosing symbol of every hit. mode "pattern" matches syntax with metavariables (`console.log($A)`), independent of formatting. For a known identifier use find_symbol.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `query` | string | required | A description ("where are passwords hashed"), the text to find, or the syntax pattern, depending on `mode`. In a pattern `$NAME` matches one node and `$$$NAME` a list. |
| `mode` | "meaning" \| "text" \| "pattern" | optional | "meaning" (default), "text" or "pattern". _(default "meaning")_ |
| `path` | string | optional | Restrict to file paths containing this text (a folder prefix or a file). |
| `language` | string | optional | Language id as listed by project_info, e.g. "typescript". Required for mode "pattern". |
| `kind` | string | optional | Only symbols of this kind ("function", "class", "method", ...); mode "meaning" only. |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(min 1, max 200, default 20)_ |

**Returns.** Ranked matches with path and line. "meaning" adds a relevance score and says in `searchMode` whether vectors were used ("keyword-only" means the index has no embeddings). "text" adds the enclosing symbol. "pattern" adds the captured metavariables.

### `get_config_usage`

Find where an environment variable or config key is read (process.env, config.get, .env files).

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `key` | string | one of* | Variable or config key; substring match. Give at least one of key, path, kind. |
| `path` | string | one of* | Only usages in this file. |
| `kind` | "env" \| "config-get" \| "dotenv" \| "env-file-reference" | one of* | Only this usage kind. |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(default 50)_ |

\* give at least one of: `key`, `path`, `kind`.

**Returns.** items[]: usages with kind ("env", "config-get", "dotenv", "env-file-reference"), path, line and the source line in `excerpt`.

### `structural_rule_test`

Run a structural rule pack against the project (a lint-style check) without changing anything.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `rules` | string | one of* | Rule pack as JSON (or simple YAML) text: {"rules":[{"id","language","pattern","message","severity":"info\|warning\|error"}]}. Give rules or rulePath. |
| `rulePath` | string | one of* | Project-relative path of a rule pack file. |
| `path` | string | optional | Restrict testing to this path. |
| `maxResults` | integer | optional | Maximum matches reported. _(min 1)_ |

\* give at least one of: `rules`, `rulePath`.

**Returns.** items[]: one per violation (kind "rule:<severity>", name = rule message, metadata.ruleId). metadata.passed is true when there are no violations; a malformed pack returns INVALID_RULE_PACK.

## Navigating symbols and dependencies

### `find_symbol`

Jump to the definition of a function, class, method or constant from (part of) its name. Unlike Grep it returns definitions only, not every mention, with kind and signature.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `name` | string | required | Symbol name or a fragment of it; matching is partial and case-insensitive. |
| `kind` | string \| string[] | optional | Restrict to symbol kinds such as "function", "class", "method", "interface", "constant"; one value or a list. |
| `language` | string \| string[] | optional | Restrict to language ids as listed by project_info (e.g. "typescript", "python"); one value or a list. |
| `path` | string | optional | Keep only symbols whose file path starts with, or contains, this text. |
| `exportedOnly` | boolean | optional | When true, return only exported (public) symbols. _(default false)_ |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(default 20)_ |

**Returns.** One line per symbol: name, kind, path:line and signature. The `id` can be passed to explain_symbol and impact.

### `find_tests`

Find the test files that exercise a file or symbol, to know what to run after a change.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | one of* | Project-relative file path using forward slashes, exactly as printed by list_files. |
| `fileId` | string | one of* | File id; alternative to `path`. |
| `symbolId` | string | one of* | Symbol id; alternative to `path`. |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(default 20)_ |

\* give at least one of: `path`, `fileId`, `symbolId`.

**Returns.** Test files with the reason each was linked. An empty list means no test is linked in the index (naming/import heuristics), not that none exists.

## Understanding code

### `explain_symbol`

Everything the index knows about one symbol in a single call: signature, who calls it, what it calls, members, tests, complexity and recent git activity. Use it instead of reading the file and grepping for callers.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `id` | string | one of* | Symbol id from another result. Give this or `name`. |
| `name` | string | one of* | Symbol name when you have no id; add `path` if the name is not unique. |
| `path` | string | optional | File path used only to disambiguate `name`. |
| `limit` | integer | optional | Maximum callers/callees/members listed per section (default 20). _(default 20)_ |
| `minConfidence` | integer | optional | Hide calls/callers whose edge confidence is below this (0–100, default 0). _(default 0)_ |

\* give at least one of: `id`, `name`.

**Returns.** Signature, visibility, calls, calledBy, members, complexity and reference count, each with the confidence of the underlying edges. `truncated` lists sections that were cut. Diagnostics are empty unless the index was built with --lsp-diagnostics.

### `file_outline`

Look at a file before deciding to read it. "summary" (default) gives its role, public API, imports and exports in a few lines; "symbols" lists every symbol with its line range; "folded" returns the source with bodies collapsed. All three cost a fraction of reading the file.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | required | Project-relative file path using forward slashes, exactly as printed by list_files. |
| `detail` | "summary" \| "symbols" \| "folded" | optional | "summary" (default), "symbols" or "folded". _(default "summary")_ |
| `maxTokens` | integer | optional | Token cap for the "folded" view. _(min 100, max 20000)_ |

**Returns.** "summary": a text card plus the public symbols. "symbols": name, kind, lines and signature per symbol. "folded": the source where omitted ranges are replaced by "… <line>".

### `syntax_tree_dump`

Debug aid: dump the parse tree of a file to see why a structural pattern does or does not match.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | required | Project-relative file path using forward slashes, exactly as printed by list_files. |
| `language` | string | required | Language id used to parse the file. |

**Returns.** items[0].excerpt: JSON tree of the file as the structural engine sees it.

## Reading source

### `read_code`

Read source lines of an indexed file by line range. Use it after find_symbol, search or file_outline told you which lines matter; the line numbers those tools print can be passed straight in.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | required | Project-relative file path using forward slashes, exactly as printed by list_files. |
| `startLine` | integer | optional | First line to read, 1-based (default 1). _(min 1)_ |
| `endLine` | integer | optional | Last line to read, inclusive (default startLine + 199). _(min 1)_ |

**Returns.** The requested lines, numbered. Without a range only the first 200 lines are returned. Errors: NOT_FOUND (unknown path), OUT_OF_RANGE (startLine is past the end of the file).

## Impact, risk and history

### `impact`

Before changing a file or symbol, see what would be affected. By default it lists what depends on the target, ranked by how certain each link is (Grep finds mentions, not dependents). direction "dependencies" lists what the target itself uses. With `change` it dry-runs a rename, move or delete and lists the references that would break; nothing is written.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `target` | string | required | A project-relative file path, a symbol name, "path::name" or an id from another result. |
| `direction` | "dependents" \| "dependencies" | optional | "dependents" (default) = what depends on the target; "dependencies" = what the target depends on. _(default "dependents")_ |
| `change` | "rename" \| "move" \| "delete" | optional | Dry-run this change to a symbol: "rename", "move" or "delete". |
| `newName` | string | optional | New name; required with change "rename". |
| `newPath` | string | optional | New project-relative file path; required with change "move". |
| `depth` | integer | optional | Hops to follow, 1–3 (default 2 for dependents, 1 for dependencies). _(min 1, max 3)_ |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(min 1, max 200, default 30)_ |

**Returns.** Affected files and symbols with depth, confidence and how each link was found; `truncated` says whether the list is complete. With `change`: the broken references (file, line, relation) and whether the change is safe.

### `git_history`

view "recent" (default): the latest commits for the project or one file, to learn what changed and who touched it. view "hotspots": files that change often and are complex, which deserve extra care or tests.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `view` | "recent" \| "hotspots" | optional | "recent" (default) or "hotspots". _(default "recent")_ |
| `path` | string | optional | Only commits touching this file; view "recent" only. |
| `since` | string | optional | ISO date (e.g. 2026-01-31); only commits after it; view "recent" only. |
| `limit` | integer | optional | Number of commits examined or hotspots returned (default 10). _(min 1, max 100, default 10)_ |

**Returns.** "recent": commits with hash, date, subject and author; `isGitRepository` separates "not a git repo" from "no commits". "hotspots": files with commit count and score components.

### `detect_architecture_violations`

Audit the whole project for layer bypasses (e.g. controller → repository), circular dependencies and similar rule violations.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `checkCyclesOnly` | boolean | optional | When true, only report circular dependencies and skip layer rules. |

**Returns.** items[]: one per violation (ruleId, severity, description, suggestion). metadata.report groups circularDependencies and layerViolations; totalViolations is the count.

## Guarded edits (opt-in)

### `edit_plan`

Step 1 of a guarded edit: describe text replacements and get a plan with a diff preview. Writes nothing. Listed only when the server runs with transactional edits enabled (a direct call otherwise answers DISABLED).

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `edits` | object[] | required | Replacements to make. Each needs path, start/end (UTF-16 offsets), replacement text and expectedHash of the current file text so a changed file is rejected. |
| `source` | "structural-search" \| "client" | optional | "client" for edits you wrote yourself, "structural-search" for edits derived from pattern-search matches. |

**Returns.** metadata: planId, per-edit diff preview and validation. Next: edit_approve → edit_apply.

### `edit_approve`

Step 2: approve a previewed plan. Approval alone changes no file.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `planId` | string | required | planId returned by edit_plan. |

**Returns.** metadata: planId and approvalToken (needed by edit_apply).

### `edit_apply`

Step 3: apply an approved plan atomically; originals are journaled so edit_rollback can undo it.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `planId` | string | required | planId returned by edit_plan. |
| `approvalToken` | string | required | Token returned by edit_approve for this plan. |

**Returns.** metadata: transactionId and status. Fails if the plan is unapproved, the token is wrong or a file changed since planning.

### `edit_rollback`

Undo an applied transaction from its journal.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `transactionId` | string | required | transactionId returned by edit_apply. |

**Returns.** metadata: transactionId and the resulting status.

### `edit_status`

Inspect journaled transactions (status, files, diff) without changing anything.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `transactionId` | string | optional | Show only this transaction; omit to list recent ones. |
| `limit` | integer | optional | Maximum transactions returned. _(min 1, max 1000)_ |

**Returns.** items[]: transactions with metadata.status, planId, paths, editCount, updatedAt.

## Experimental (opt-in)

### `symbol_references`

Experimental (TypeScript only, needs the `semantic-graph` capability). References to a symbol with explicit resolution confidence.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `symbolId` | string | one of* | Symbol id. Give one of symbolId, symbolKey, name. |
| `symbolKey` | string | one of* | Stable symbolKey from a symbol result. |
| `name` | string | one of* | Symbol name. |
| `minConfidence` | "exact" \| "heuristic" \| "ambiguous" \| "unresolved" | optional | Lowest confidence class to include. |
| `limit` | integer | optional | Maximum references returned. _(min 1, max 10000)_ |
| `snapshotHandle` | string | optional | Handle from a previous response to query the same snapshot. |

\* give at least one of: `symbolId`, `symbolKey`, `name`.

**Returns.** items[]: references with confidence (exact/heuristic/ambiguous/unresolved) and provenance; metadata.snapshotHandle for follow-up calls. Stale handles fail closed.

Experimental bounded impact analysis that states where each constraint came from.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `symbolId` | string | required | Symbol id to analyse. |
| `includeHeuristic` | boolean | optional | Include heuristic (non-exact) edges; default false. |

### `context_build_v4`

Experimental deterministic context builder with a hard token budget.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `seed` | string | required | Starting symbol, file or text (1–200 chars). _(min length 1, max length 200)_ |
| `budgetTokens` | integer | optional | Hard token budget, 1–100000. _(min 1, max 100000)_ |
| `limit` | integer | optional | Maximum blocks, 1–1000. _(min 1, max 1000)_ |
| `goal` | string | optional | Natural-language goal; only selects retrieval direction. _(min length 1, max length 500)_ |

**Returns.** items[]: selected context blocks within budgetTokens.

### `semantic_rename_v4`

Experimental rename planner (needs transactional edits enabled). Produces an edit plan; apply it with edit_approve/edit_apply.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `symbolId` | string | required | Symbol to rename. |
| `replacement` | string | required | New identifier ([A-Za-z_$][\w$]*). |
| `includeHeuristic` | boolean | optional | Also rename heuristic (non-exact) references; default false. |

**Returns.** metadata: planId and affected references; heuristic references are flagged.
