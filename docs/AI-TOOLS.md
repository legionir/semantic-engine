# Semantic Engine — AI tool reference

_Generated by `node scripts/gen-ai-tools-doc.js` from the tool registry; do not edit by hand._

38 tools. They are served over MCP (`tools/list`, `tools/call`). Through the gateway each tool also takes a `project` parameter.

Every result is `{ success, items[], metadata, context? }` with `projectId` and `indexGeneration` added by the server; see the skill (`skills/semantic-engine/SKILL.md`) for how to read `truncated`, empty results and `warnings`.

## Orientation

### `project_info`

Orientation call: project root, index generation/time, languages and, per language, how deep the analysis goes (symbols/callGraph/status). Call first in a session.

_No parameters._

**Returns.** items[0].metadata: root, rootPath, generatedAt, snapshotId, languages[], languageSupport{lang:{symbols,callGraph,status}}, adapter status.

### `project_list_files`

List indexed files (path order) to learn the layout or get exact paths for other tools.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `language` | string | optional | Only files of this language id. |
| `limit` | integer | optional | Maximum files returned (default 1000). _(min 1, max 10000)_ |

**Returns.** items[]: files with path, language, size, lines, hash, generated, binary. metadata: matchCount, truncated, limit.

### `diagnostics_get`

Read compiler/language-server diagnostics stored in the index.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | optional | Project-relative file path using forward slashes, exactly as printed by project_list_files. Omit for project-wide diagnostics. |
| `severity` | string | optional | Only this severity, e.g. "error" or "warning". |
| `limit` | integer | optional | Maximum diagnostics returned (default 1000). _(min 1, max 10000)_ |

**Returns.** items[]: diagnostics (message, severity, code, line, column). metadata.warning is present when no diagnostics pass was recorded — then an empty list does NOT mean the code is clean.

### `gains_report`

Estimate how many tokens code_fold / reading by range saves compared with reading whole files.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | optional | One file; omit for every indexed file. |
| `maxTokens` | integer | optional | Folded-token budget to compare against; default is 35% of the estimated full size. _(min 1)_ |

**Returns.** items[]: per file fullTokensEstimate, foldedTokensBudget, avoidedTokensEstimate, compressionRatio. Estimates from line counts, not measurements.

## Finding things

### `semantic_search`

Find symbols and files from a natural-language description when you do not know their names. Ranked by keyword match, vector similarity (when the index has embeddings) and importance signals.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `query` | string | required | What you are looking for, in plain words ("where are passwords hashed"). |
| `filters` | object | optional | Narrowing filters: language, kind, path (prefix/substring) and exportedOnly, same meaning as in find_symbol. |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(default 20)_ |
| `mode` | "keyword" \| "vector" \| "hybrid" | optional | "keyword", "vector" or "hybrid" (default). "vector" fails or degrades when the index has no embeddings. _(default "hybrid")_ |
| `minScore` | number | optional | Drop results whose final ranked score is below this value (0–1). |
| `useEmbeddings` | boolean | optional | Set false to skip vector scoring even when embeddings exist (faster, keyword only). _(default true)_ |

**Returns.** items[]: symbols/files with relevanceScore 0–1 and metadata.signals explaining the ranking. metadata.searchMode says what actually ran ("keyword-only" when the index has no vectors — see degradedReason); an empty result with that mode means "no keyword hit", not "nothing relevant exists".

### `discover_context`

Start here for an unfamiliar task: give only a plain-language description and get candidate files/symbols with the reason each was chosen. Returns candidates, not source text — follow with assemble_context or code_read.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `task` | string | required | Plain-language description of what you want to do. |
| `limit` | integer | optional | Maximum candidates returned (default 20). _(default 20)_ |
| `expansionDepth` | integer | optional | Graph hops to expand from the seed hits (default 2). _(default 2)_ |
| `seedLimit` | integer | optional | Number of search hits used as seeds (default 8). _(default 8)_ |
| `filesPerModule` | integer | optional | Files taken from each matching architecture module (default 3). _(default 3)_ |
| `maxNodes` | integer | optional | Ceiling on graph nodes visited during expansion (default 200). _(default 200)_ |
| `maxPerFile` | integer | optional | Maximum candidates from any single file, so one crowded file cannot take the whole budget _(default 2)_ |
| `includeTests` | boolean | optional | Also return test files among the candidates (default false). _(default false)_ |

**Returns.** items[]: candidates with relevanceScore and metadata.origin ("search", "blueprint", "graph") and graphHops; `excerpt` explains why it was selected.

### `get_config_usage`

Find where an environment variable or config key is read (process.env, config.get, .env files).

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `key` | string | one of* | Variable or config key; substring match. Give at least one of key, path, kind. |
| `path` | string | one of* | Only usages in this file. |
| `kind` | "env" \| "config-get" \| "dotenv" \| "env-file-reference" | one of* | Only this usage kind. |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(default 50)_ |

\* give at least one of: `key`, `path`, `kind`.

**Returns.** items[]: usages with kind ("env", "config-get", "dotenv", "env-file-reference"), path, line and the source line in `excerpt`.

### `search_text`

Exact (case-insensitive) text search through indexed source files — for strings, log messages, TODOs. For meaning-based search use semantic_search.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `query` | string | required | Text to find; plain substring, not a regex. _(min length 1)_ |
| `path` | string | optional | Only search this file path. |
| `limit` | integer | optional | Maximum matches returned (default 100). _(min 1, max 1000)_ |

**Returns.** items[]: one per matching line with path, line (the real line), excerpt (the line) and metadata.column / enclosingSymbol (symbol id containing the match).

### `structural_search`

Find code by syntax shape with metavariables (e.g. `console.log($A)`), which text search cannot express. Read-only.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `pattern` | string | required | Code pattern; `$NAME` matches one node, `$$$NAME` a list. _(min length 1)_ |
| `language` | string | required | Language id of the pattern, e.g. "typescript", "python". |
| `path` | string | optional | Restrict to this file path or folder prefix. |
| `maxResults` | integer | optional | Maximum matches (default 100). _(min 1, max 10000)_ |
| `ruleId` | string | optional | Optional label copied onto each match as metadata.ruleId; it does not select a rule. |

**Returns.** items[]: matches with path, line and metadata.captures (metavariable → matched text), start/end offsets. Languages without a structural grammar fail explicitly.

### `structural_rule_test`

Run a structural rule pack against the project (a lint-style check) without changing anything.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `rules` | string | one of* | Rule pack as JSON (or simple YAML) text: {"rules":[{"id","language","pattern","message","severity":"info\|warning\|error"}]}. Give rules or rulePath. |
| `rulePath` | string | one of* | Project-relative path of a rule pack file. |
| `path` | string | optional | Restrict testing to this path. |
| `maxResults` | integer | optional | Maximum matches reported. _(min 1)_ |

\* give at least one of: `rules`, `rulePath`.

**Returns.** items[]: one per violation (kind "rule:<severity>", name = rule message, metadata.ruleId). metadata.passed is true when there are no violations; a malformed pack returns INVALID_RULE_PACK.

## Navigating symbols and dependencies

### `find_symbol`

Locate a function, class, method or constant by (part of) its name. Use symbol_find instead when you need an exact-name lookup.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `name` | string | required | Symbol name or a fragment of it; matching is partial and case-insensitive. |
| `kind` | string \| string[] | optional | Restrict to symbol kinds such as "function", "class", "method", "interface", "constant"; one value or a list. |
| `language` | string \| string[] | optional | Restrict to language ids as listed by project_info (e.g. "typescript", "python"); one value or a list. |
| `path` | string | optional | Keep only symbols whose file path starts with, or contains, this text. |
| `exportedOnly` | boolean | optional | When true, return only exported (public) symbols. _(default false)_ |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(default 20)_ |

**Returns.** items[]: one per symbol with id, name, kind, path, line and signature in `excerpt`. The `id` can be passed to explain_symbol, impact_analysis and get_dependencies. metadata: matchCount, truncated, limit.

### `get_dependencies`

See what a file or symbol depends on (forward) or what depends on it (backward). For "what breaks if I change this" prefer impact_analysis, which ranks by confidence.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `id` | string | required | A file path as printed by project_list_files, a fileId, or a symbolId taken from another tool result. |
| `direction` | "forward" \| "backward" | required | "forward" = what this depends on; "backward" = what depends on this. |
| `level` | "file" \| "symbol" | optional | "file" walks import edges between files; "symbol" walks call edges between symbols. _(default "file")_ |
| `depth` | integer | optional | Number of hops to follow, 1–3. Larger values grow the result quickly. _(min 1, max 3, default 1)_ |
| `kind` | "import" \| "package" \| "dynamic-import" \| "called-by" \| "all" | optional | Edge kind filter; "all" (default) mixes imports, packages, dynamic imports and call edges. _(default "all")_ |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(default 50)_ |

**Returns.** items[]: related files, symbols or packages (kind "import", "package", "called-by"…), each with metadata.dependents. metadata: truncated, limit.

### `find_tests`

Find the test files that exercise a file or symbol, to know what to run after a change.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | one of* | Project-relative file path using forward slashes, exactly as printed by project_list_files. |
| `fileId` | string | one of* | File id; alternative to `path`. |
| `symbolId` | string | one of* | Symbol id; alternative to `path`. |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(default 20)_ |

\* give at least one of: `path`, `fileId`, `symbolId`.

**Returns.** items[]: test files with the reason they were linked. An empty list means no test is linked in the index (naming/import heuristics), not that none exists.

### `symbol_find`

Exact-name symbol lookup (case-insensitive), deterministic order. Use find_symbol for partial/fuzzy matching.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `query` | string | required | Symbol name (exact, case-insensitive). _(min length 1)_ |
| `kind` | string | optional | Only this symbol kind. |
| `path` | string | optional | Only symbols in this file path. |
| `limit` | integer | optional | Maximum results (default 100). _(min 1, max 1000)_ |

**Returns.** items[]: symbols with id, kind, path, line, signature; metadata: matchCount, truncated, limit.

## Understanding code

### `get_file_summary`

Get the role, public API, imports and exports of one file in a few lines, before deciding whether to read it. Cheaper than code_read.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | one of* | Project-relative file path using forward slashes, exactly as printed by project_list_files. |
| `fileId` | string | one of* | File id from another tool result; use instead of `path`. |

\* give at least one of: `path`, `fileId`.

**Returns.** items[]: the file's symbols (id, kind, line, signature). `context`: a text card with role, language, line count, summary, public API, imports and exports.

### `assemble_context`

Build one token-budgeted bundle of the files and symbols needed for a coding task, starting from files/symbols you already know. Use discover_context first when you do not know where to start.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `task` | string | required | One or two sentences describing the change; used to rank related files. |
| `targetFiles` | string[] | optional | Project-relative paths of files you are going to change; always included. |
| `targetSymbols` | string[] | optional | Symbol ids of symbols you are going to change; always included. |
| `maxTokens` | integer | optional | Token budget of the assembled context (default 4000). _(default 4000)_ |
| `includeTests` | boolean | optional | Include tests linked to the targets (default true). _(default true)_ |
| `includeRecentChanges` | boolean | optional | Add recent git commits touching the targets (default false). _(default false)_ |
| `dependencyDepth` | integer | optional | How many dependency hops around the targets to include (default 1). _(default 1)_ |
| `explain` | boolean | optional | Add the ranking signals behind each item. _(default false)_ |

**Returns.** items[]: ranked files/symbols with metadata.section ("targetFiles", "relatedFiles", "tests"…) and graphHops. `context`: the assembled text within maxTokens. Targets and tests get a guaranteed share of the budget.

### `explain_symbol`

Everything known about one symbol in a single call (signature, complexity, callers, callees, tests, git, diagnostics) with the confidence of each part.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `id` | string | optional | Symbol id. Give this or `name`. |
| `name` | string | optional | Symbol name when you have no id; add `path` if the name is not unique. |
| `path` | string | optional | File path used only to disambiguate `name`. |
| `limit` | integer | optional | Maximum callers/callees/members listed per section (default 20). _(default 20)_ |
| `minConfidence` | integer | optional | Hide calls/callers whose edge confidence is below this (0–100, default 0). _(default 0)_ |

**Returns.** items[0].metadata: signature, visibility, calls[], calledBy[], members[], complexity, referenceCount, plus per-part trust/basis; `truncated` lists which sections were cut. Diagnostics are empty unless the index was built with --lsp-diagnostics: check diagnosticsRun before reading an empty list as "clean".

### `symbol_inspect`

Identity card of one symbol: stable symbolKey, range, signature hash, confidence. Lighter than explain_symbol.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `id` | string | one of* | Symbol id. Give id or name. |
| `name` | string | one of* | Exact symbol name when you have no id. |
| `path` | string | optional | File path to disambiguate `name`. |

\* give at least one of: `id`, `name`.

**Returns.** items[]: matching symbols with metadata.symbolKey, endLine, confidence, exported. NOT_FOUND when nothing matches.

### `code_outline`

Structural outline (all symbols, in order) of one file. Use compact:true to save about two thirds of the tokens.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | one of* | Project-relative file path using forward slashes, exactly as printed by project_list_files. Give path or fileId. |
| `fileId` | string | one of* | File id; alternative to path. |
| `includeRanges` | boolean | optional | Include start/end line ranges (default true). |
| `compact` | boolean | optional | Return only name, kind, lines and signature per symbol. |

\* give at least one of: `path`, `fileId`.

**Returns.** items[]: symbols with kind, line, signature and metadata.endLine/range; compact:true keeps only name, kind, lines and signature.

### `syntax_tree_dump`

Debug aid: dump the parse tree of a file to see why a structural pattern does or does not match.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | required | Project-relative file path using forward slashes, exactly as printed by project_list_files. |

## Reading source

### `code_read`

Read actual source text, bounded. Use after the index tools told you where to look; use code_fold first for a cheaper structural view.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | one of* | Project-relative file path using forward slashes, exactly as printed by project_list_files. Give one of path, fileId, handle. |
| `fileId` | string | one of* | File id; alternative to path. |
| `handle` | string | one of* | Handle from an earlier code_read/code_fold result; fails with STALE_HANDLE if the file changed. |
| `start` | integer | optional | Start offset in UTF-16 code units (not bytes or lines), 0-based. _(min 0)_ |
| `end` | integer | optional | End offset (exclusive) in UTF-16 code units; must be ≥ start. _(min 0)_ |
| `maxResultBytes` | integer | optional | Cap on returned text size in bytes; the result says truncated:true when it cut. _(min 1, max 1000000)_ |

\* give at least one of: `path`, `fileId`, `handle`.

**Returns.** items[0].excerpt: the text; metadata: handle (re-readable, bound to the file version), start/end (UTF-16 offsets), truncated, returnedTokens. Errors: NOT_FOUND, OUT_OF_RANGE, STALE_HANDLE (file changed since the handle was issued).

### `code_fold`

Read a file with bodies collapsed ("… 13") so you see its structure for a fraction of the tokens; then code_read the part you need.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `path` | string | one of* | Project-relative file path using forward slashes, exactly as printed by project_list_files. Give path or fileId. |
| `fileId` | string | one of* | File id; alternative to path. |
| `level` | integer | optional | Fold level 0–4 (default 2). 0 keeps every line (no folding); 1–2 keep each symbol's first and last line; 3–4 also keep the first few lines of each body. _(min 0, max 4)_ |
| `maxTokens` | integer | optional | Token cap for the folded output. _(min 1, max 100000)_ |
| `comments` | "strip" \| "doc-only" \| "keep" | optional | "strip" removes comments, "doc-only" keeps doc comments, "keep" keeps all. |

\* give at least one of: `path`, `fileId`.

**Returns.** items[0].excerpt: folded source where omitted ranges are replaced by "… <line>"; metadata has a handle and token counts.

## Impact, risk and history

### `impact_analysis`

Before changing a file or symbol, list what depends on it (reverse dependencies), ranked by confidence. Use simulate_mutation for a rename/move/delete you are about to do.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `id` | string | required | A file path as printed by project_list_files, a fileId, or a symbolId taken from another tool result. A module or package id is also accepted. |
| `level` | "file" \| "symbol" \| "any" | optional | Result granularity: "file", "symbol" or "any". _(default "file")_ |
| `depth` | integer | optional | Hops to follow upstream (default 2). _(default 2)_ |
| `limit` | integer | optional | Maximum number of items to return; when more exist the result says `truncated: true` and `matchCount` holds the real total. _(default 30)_ |
| `minConfidence` | integer | optional | Ignore edges below this confidence (0–100, default 70). 0 also includes name-match guesses. _(default 70)_ |

**Returns.** items[]: impacted files/symbols with relevanceScore and metadata.depth, pathConfidence and `via` (how the edge was found). metadata: truncated/droppedByLimit/traversalExhausted tell whether the list is complete. An unknown id returns success:false.

### `get_recent_changes`

See the latest commits for the project (or one file) to learn what changed recently and who touched it.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `workspaceRoot` | string | optional | Directory to run git in; normally omit it. Relative values resolve against the indexed project root. |
| `path` | string | optional | Project-relative file path using forward slashes, exactly as printed by project_list_files. |
| `limit` | integer | optional | Number of most recent commits examined (default 10). _(default 10)_ |
| `since` | string | optional | ISO date (e.g. 2026-01-31); only commits after it are kept — applied within the examined window. |

**Returns.** items[]: commits (id = full hash, name = subject, excerpt = date | subject, source = author). metadata.isGitRepository separates "not a git repo" from "no commits"; examinedCommits and truncated describe the window.

### `simulate_mutation`

Dry-run a rename, delete or move in the index and list the references it would break. Writes nothing; run it before edit_plan.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `actionType` | "rename_symbol" \| "delete_symbol" \| "move_symbol" | required | "rename_symbol", "delete_symbol" or "move_symbol". |
| `targetSymbolId` | string | required | Symbol id (or "path::name") to mutate. |
| `newName` | string | optional | New name; required for rename_symbol. |
| `newPath` | string | optional | New project-relative file path; required for move_symbol. |

**Returns.** metadata.diff: affectedSymbolsCount, brokenReferences[] (callerFile, callerLine, relation) and isSafe. items[] lists the broken references.

### `detect_architecture_violations`

Audit the whole project for layer bypasses (e.g. controller → repository), circular dependencies and similar rule violations.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `checkCyclesOnly` | boolean | optional | When true, only report circular dependencies and skip layer rules. |

**Returns.** items[]: one per violation (ruleId, severity, description, suggestion). metadata.report groups circularDependencies and layerViolations; totalViolations is the count.

### `get_git_hotspots`

Find risky files: frequently changed and complex. Good targets for extra review or tests.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `limit` | integer | optional | Maximum hotspots returned (default 10). |

**Returns.** metadata.hotspots[] with score components; `context` states how many were found. Empty means no history data (not a git repo, or no commits), not "no risk".

## Guarded edits (opt-in)

### `edit_plan`

Step 1 of a guarded edit: describe text replacements and get a plan with a diff preview. Writes nothing. Requires the server to run with transactional edits enabled; otherwise returns DISABLED.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `edits` | object[] | required | Replacements to make. Each needs path, start/end (UTF-16 offsets from code_read), replacement text and expectedHash of the current file text so a changed file is rejected. |
| `source` | "structural-search" \| "client" | optional | "client" for edits you wrote yourself, "structural-search" for edits derived from structural_search matches. |

**Returns.** metadata: planId, per-edit diff preview and validation. Next: edit_approve → edit_apply.

### `edit_approve`

Step 2: approve a previewed plan. Approval alone changes no file.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `planId` | string | required | planId returned by edit_plan. |

**Returns.** metadata: planId and approvalToken (needed by edit_apply).

### `edit_apply`

Step 3: apply an approved plan atomically; originals are journaled so edit_rollback can undo it.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `planId` | string | required | planId returned by edit_plan. |
| `approvalToken` | string | required | Token returned by edit_approve for this plan. |

**Returns.** metadata: transactionId and status. Fails if the plan is unapproved, the token is wrong or a file changed since planning.

### `edit_rollback`

Undo an applied transaction from its journal.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `transactionId` | string | required | transactionId returned by edit_apply. |

**Returns.** metadata: transactionId and the resulting status.

### `edit_status`

Inspect journaled transactions (status, files, diff) without changing anything.

| Parameter | Type | Need | Meaning |
|---|---|---|---|
| `transactionId` | string | optional | Show only this transaction; omit to list recent ones. |
| `limit` | integer | optional | Maximum transactions returned. _(min 1, max 1000)_ |

**Returns.** items[]: transactions with metadata.status, planId, paths, editCount, updatedAt.
