# موارد باز، ناقص و انجام‌نشده

تاریخ: ۲۰۲۶-۱۰-۲۵ · مبنا: `main` در `legionir/semantic-engine` بعد از مرج PR #10 (`a6f3a6b`)؛ پکیج اکنون در ریشهٔ مخزن است (مسیرها بدون پیشوند `semantic-engine/`)

این تنها فایل پیگیری کارهای باقی‌مانده است. گزارش‌های وضعیت فازها، پوشه‌های evidence، اسکریپت‌ها و fixtureهای regate و سندهای پلن/پرامپت که کارشان تمام شده بود از درخت حذف شدند و در تاریخچهٔ git (commit `0d8d4cf`) هستند.
هر مورد مربوط به ریپوی `semantic-engine-structured-ai` عمداً کنار گذاشته شده و اینجا نیست.

## ۱. پرفرمنس

| مورد | وضعیت و جزئیات |
|---|---|
| هدف‌های ۶ s / ۲ s | گیت واقعی طبق D-0030 «سرد ≤ ۸ s و ایندکس مجدد ≤ ۵ s» است (ران‌ر: ۷٫۶۵ / ۴٫۹۳). پروفایل CPU یک ایندکس کاملاً-کش‌خورده (۵٫۴ s) مسطح است و نقطهٔ داغ واحدی ندارد: GC ≈ ۰٫۷ s، هش ≈ ۰٫۴ s، خواندن فایل‌ها ≈ ۰٫۶ s، parse دوبارهٔ TypeScript برای complexity ≈ ۱ s، نوشتن JSON ≈ ۰٫۵ s. تنها قدم مشخص و کم‌ریسک بعدی: کش‌کردن complexity هر فایل کنار extraction cache (حدود ۱ s). رسیدن به ۲ s ایندکس افزایشی کامل می‌خواهد و فقط با نیاز واقعی توجیه دارد |
| تغییر یک فایل در `watch`/`start` | اندازه‌گیری روی یک مخزن ۶۳۳ فایلی (۱ فایل تغییر + ۱۳۶ وابسته): موتور افزایشی بعد از رفع بازسازی مکرر آرایه‌ها از ≈۵٫۵ s به ≈۲٫۹ s رسید؛ کل به‌روزرسانی ≈۶٫۶ s (روی این ماشین کندتر از runner). ≈۲٫۳ s باقی‌مانده نوشتن کامل ایندکس ۴۸ مگابایتی و blueprint است؛ هر تغییر کل فایل را بازنویسی می‌کند. قدم بعدی: نوشتن جمع‌وجورتر یا تقسیم artifact، که قرارداد خروجی را عوض می‌کند |
| بنچمارک و eval روی یک مخزن | فقط خود پروژه اندازه گرفته شده؛ مخزن بزرگ یا چندزبانه ممکن است سهم مرحله‌ها را عوض کند |

## ۵. معماری و قراردادها

| ast-grep برای PHP | Python با `@ast-grep/lang-python` (اختیاری) کار می‌کند. PHP نه: sigil گرامر PHP همان `$` است و الگوهای metavariable هیچ‌چیز match نمی‌کنند (اندازه‌گیری شد) |
