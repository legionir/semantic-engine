## ۲. کارهای انجام‌شده

### رفع باگ و امنیت
- `start --port` دیگر توسط `uiPort` کانفیگ نادیده گرفته نمی‌شود.
- `start` با مدل embedding دانلودنشده کرش نمی‌کند: fallback به hashing به فرایند `watch` هم منتقل می‌شود.
- سرور پوشه‌ی مدل‌ها را مثل CLI از `SEMANTIC_ENGINE_MODELS_DIR` می‌خواند.
- `PUT /api/v1/settings`: آدرس‌ها با همان بررسی SSRF مسیر jobs اعتبارسنجی می‌شوند؛ نام متغیر کلید API فقط با پیشوندهای مجاز پذیرفته می‌شود (در config ورکرهای gateway هم).
- timeout شروع (`SEMANTIC_ENGINE_START_TIMEOUT_MS`) اعتبارسنجی می‌شود و child بعد از timeout کشته می‌شود.
- `--help`/`--version` دیگر `config.json` نمی‌نویسند.
- سرور درخواست absolute-form را می‌فهمد.
- پنل: مدل در حال دانلود از انتخاب نمی‌افتد و polling بعد از خطا ادامه می‌دهد.
- `config.json`: ذخیره با قفل بین‌فرایندی و بدون حذف کلیدهای ناشناخته.
- تنظیمات scan پنل به `index` و `watch` هم می‌رسد.
- `StaticAssetServer`: بررسی مسیر با `path.sep` (پوشه‌ی هم‌پیشوند مثل `public-evil` دیگر رد نمی‌شود).
- `HttpGuard`: ریشه‌ی شکست پراکنده‌ی تست ۴۱۳ پیدا و رفع شد (`response.socket` پس از finish توسط Node جدا می‌شود). حالا اتصال باز می‌ماند و بدنه‌ی رد‌شده با سقف ۳۲ مگابایت و ۵ ثانیه تخلیه می‌شود.
- تست LSP registry دیگر به PATH میزبان وابسته نیست.

## ۵. تصمیم‌های معماری گرفته‌شده (توسط من، با دلیل)

1. **push protection را دور نزدم.** دو fixture تست (کلید نمونه‌ی Stripe و توکن Slack) را در کد تکه‌تکه کردم (مقدار زمان اجرا همان است) به‌جای bypass.
2. **`main` را از کامیت ایمپورت ساختم** تا PR همه‌ی تغییرها را نشان دهد.
3. **`chokidar` ۴، نه ۵** (۵ فقط ESM است و `FileWatcher` با `require` بارگذاری می‌کند).
4. **`@xenova/transformers` را کاهش نسخه ندادم**؛ `sharp`/`protobufjs` با `overrides` وصله شدند.
5. **allowlist برای نام متغیر کلید API** با پیشوند، قابل‌گسترش با `SEMANTIC_ENGINE_API_KEY_ENV_PREFIXES`. گزینه‌ی خط فرمان محلی عمداً محدود نشد.
6. **قفل `config.json`** با فایل قفل exclusive-create و takeover بعد از ۱۰ ثانیه، نه وابستگی جدید.
7. **۴۱۳:** اتصال باز می‌ماند و بدنه تخلیه می‌شود (به‌جای بستن فوری).
8. **ریفکتور فقط رفتارحفظ‌کننده:** هر استخراج با تست کامل و در صورت لزوم مقایسه‌ی خروجی؛ وابستگی‌های کلاس با اینترفیس `deps` صریح منتقل شدند.
9. **JSON:** هر عضو آرایه با یک `JSON.stringify` بومی نوشته می‌شود، ولی سند کامل یک‌جا ساخته نمی‌شود.
10. **بودجه‌ی skip = ۱** برای تست قراردادی `mcpIndexGeneration` که به ریپوی همسایه نیاز دارد.
11. **خط پایه‌ی بنچمارک روی کانتینر توسعه ثبت شده** و job بنچمارک CI فقط اطلاعاتی است.

## ۶. تصمیم‌هایی که با شماست

1. **ایندکس افزایشی برای `index`** را به‌عنوان تصمیم محصول تأیید می‌کنید؟ قواعد ابطال کش باید تعریف شود: تغییر گزینه‌ها، نسخه‌ی extractor، حذف فایل، بردارها، git، diagnostics.
2. **سرنوشت ریپوی `semantic-engine-structured-ai`:** همگام‌سازی با ریپوی جدید، یا بایگانی/لینک به آن؟
3. **مرج PR #1:** بعد از سبز شدن CI، یا همین حالا؟
4. **تست قراردادی `mcpIndexGeneration`:** به ریپوی مصرف‌کننده منتقل شود یا vendored شود؟ تا آن موقع بودجه‌ی skip = ۱ می‌ماند.
5. **اهداف عددی «بالاترین سطح پرفرمنس»:** مثلاً ایندکس سرد زیر ۵ ثانیه؟ بدون هدف عددی، فاز ۳ پایان مشخص ندارد.
6. **فهرست پیشوندهای مجاز کلید API** (بخش ۵، مورد ۵) مناسب شماست یا پیشوند دیگری لازم است؟

## ۷. موارد کوچک و ریسک‌های باز

- نتیجه‌ی CI روی GitHub دیده نشده؛ تست ۴۱۳ زیر بار CPU مصنوعی قبلاً ۱ از ۱۰ بار شکست می‌خورد. بعد از اصلاح ۲۰ + ۱۵ اجرا بدون شکست بود، ولی تضمین مطلق نیست.
- مسیر واقعی embedding با مدل دانلودشده و `sharp ^0.35.5` اجرا نشد (فقط بارگذاری ماژول بررسی شد).
- ۳۴ آسیب‌پذیری devDependencies (زنجیره‌ی jest) فقط گزارش می‌شوند.
- تست «reaper» (`lspTesting`) به محیط وابسته است و در CI ممکن است skip شود؛ بودجه‌ی skip آن را جذب نمی‌کند.
- `--embedding-api-key-env` در CLI محدود به allowlist نیست.
- بنچمارک روی یک مخزن (خود پروژه) اندازه گرفته شده؛ مخزن بزرگ‌تر یا چندزبانه ممکن است سهم مرحله‌ها را عوض کند.
- UI فقط با تست خودکار سنجیده شده، نه اجرای واقعی.
- قفل `config.json` روی NFS تضمین ندارد.
