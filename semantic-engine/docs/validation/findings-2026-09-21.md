- **F-02** (`src/ai/tools/Phase1ReadTools.ts`): `ProjectInfoTool.execute()` had
  zero parameters, so `execute({})` did not compile and the whole
  `Phase1ReadTools.test.ts` suite was dead (0 tests reported). Fix: optional
  `_input?: AiToolInput` parameter. The suite now runs 6 tests, all passing.
- **F-03** (`src/core/codeintel/Phase2Structural.ts`): two compounding defects.
  (a) `matchLine` anchored the pattern to the full trimmed line, so
  `console.log($VALUE)` never matched `console.log(user);`. Fix: substring
  span matching with UTF-16 start/end/column of the matched span, zero-length
  matches rejected. (b) The metavariable tokenizer `/\$\$\$?.../` required two
  dollar signs, so documented single-`$NAME` captures never tokenized. Fix:
  `/\$\$\$name|\$name/`. Both previously failing tests now pass unmodified.
- **F-06** (`src/ai/tools/Phase1ReadTools.test.ts`, test-only): fixture declared
  symbol `add` as `line 2, endLine 2` while the written file spans lines 1–4
  with `return` on line 3. Honest range containment could never yield
  `enclosingSymbol: s1`. Fix: `endLine: 4` (matching the file) and the
  corresponding `symbol_inspect` expectation. Implementation untouched.
- **F-07** (`src/ai/mcp/SemanticEngineMcpServer.ts`, `src/ai/mcp/cli.ts`):
  `createRegistry` never forwarded `enablePhase2Edits` /
  `phase2JournalDirectory` / `experimental`, so Phase 2 edits were always
  `DISABLED` over MCP and Phase 3/4 tools were never listed — MCP verification
  of Phases 2–4 was impossible. Fix (additive, default-off): new optional
  `McpServerOptions` fields preserved across `reload()`, plus CLI flags
  `--allow-edits` and `--experimental <csv>` (unknown names dropped).
  Evidence: `McpPhaseGating.test.ts` (default closed, opt-in executes).
- **F-08** (`src/ai/AiToolRegistry.ts`): the projectHash-keyed result cache
  stored mutation outcomes, so a repeated identical `edit_apply` returned the
  first success without re-checking approval/preconditions. Fix: `edit_plan`,
  `edit_approve`, `edit_apply`, `edit_rollback`, and the observing
  `edit_status` bypass the cache in both directions. Evidence: MCP e2e asserts
  replay-apply fails `STALE_SNAPSHOT` and post-rollback status reads
  `rolled_back` (the latter caught the `edit_status` staleness during this
  validation).
- **F-09** (`src/core/contracts/codeintel.ts` + 4 producers): real pipeline
  indexes store `path::Name`-shaped `fullyQualifiedName` values, and
  `makeSymbolKey` rejects `::`/`#` in key parts — `symbol_references` (and
  `Phase1IndexPlatform.outline`) threw `IO_ERROR` on the real fixture index.
  Fix (additive mapping, per plan §0): exported `sanitizeKeyPart`
  (`::`→`:`, `#`→`_`; deterministic, total), applied in Phase 1 outline,
  Phase 3 keys, Phase 1 read-tool keys, and Phase 4 keys. Evidence:
  `SymbolKeyMapping.test.ts` + `phase4-bench.js` (`referencesSuccess: true`).
- **F-10** (`src/core/codeintel/Phase2Transactions.ts`,
  `src/ai/tools/Phase2StructuralTools.ts`, `src/ai/AiToolRegistry.ts`):
  `rollback`/`undo` restored originals unconditionally — external modification
  after apply was silently overwritten, violating plan §2.11. Fix:
  `TransactionRecord.after[]` (disk-verified hashes recorded at apply),
  `rollback` throws `UNDO_CONFLICT` on any mismatch/missing file or on

  Evidence: `Phase2FuzzRecovery.test.ts` (conflict case) + MCP e2e.
